**Agent Workflow Spec (AWSpec) · Juno**

**Goal**

Identify and triage P0 customer escalations into a daily prioritized top-3 risk list, grounded in customer evidence and the RocketShip Strategy One-Pager.

For each recommendation, Juno provides the customer evidence, strategic rationale, priority recommendation, confidence level, and a defensible alternative when appropriate.

The goal is to help the PM make faster, evidence-based prioritization decisions that can be confidently defended, while keeping the PM accountable for the final decision.

Primary actor: Agent + Human-in-the-loop
Autonomy level: Copilot
AI capability: Hybrid (RAG + Agentic)

Juno retrieves, analyzes, compares, scores, and drafts. The PM reviews and approves before Juno changes shared product state or communicates a recommendation.

**Trigger**

Start the workflow when:

A new message appears in #escalations tagged P0 AND the thread reaches ≥5 messages within 10 minutes.

The trigger initiates analysis only. It does not authorize Juno to publish a recommendation or modify the roadmap.

**Steps & Tools**

Pattern: ReAct — single-agent reason → act → observe loop.

**Recommendation Card**

Each escalation produces a structured recommendation containing:

Priority: P0–P3 or notRecommended

Customer problem: concise description of the escalation

Customer evidence: supporting quote or signal from the escalation

Business impact: ARR and churn risk when available

Strategic alignment: relevant RocketShip strategic pillar

Strategic citation: supporting clause from the Strategy One-Pager

Rationale: why Juno recommends the priority

Defensible alternative: a faster or higher-impact approach when the original request is not the strongest solution

Confidence: strength of the evidence supporting the recommendation

**Memory**

Episodic Memory

In scope: Tool results, retrieved strategy chunks, intermediate scores, and reasoning artifacts required during the run.

Lifetime: End of run.

No run-specific customer data persists after the workflow completes unless explicitly captured in an approved system of record.

Semantic Memory

In scope: RocketShip strategic taxonomy, Juno system instructions, prioritization rules, and approved PM preferences.

Lifetime: Persistent and refreshed when the underlying source changes.

Customer-specific contracts, escalation details, and PII are not persisted as semantic memory.

Working Memory

In scope: Current escalation thread, customer ID, ARR, retrieved strategy evidence, priority recommendation, and confidence score.

Lifetime: Current workflow only.

**Human-in-the-Loop**

The PM is the final decision-maker.

Juno may autonomously retrieve evidence, analyze escalations, rank risks, and draft recommendations.

Before any recommendation is posted to #pm-daily or creates a Jira stub, the PM must explicitly:

Approve · Edit · Reprioritize · Reject

**Confidence Handling**

Confidence ≥70%: Present as a standard recommendation for PM review.

Confidence 30–69%: Present with a "Low confidence — PM review required" warning and identify the missing or conflicting evidence.

Confidence <30%: Do not recommend a priority. Label the item "Insufficient evidence" and route it to the PM.

Confidence never bypasses PM approval.

**Success & Failure**

Success

The workflow is successful when:

Qualifying P0 escalations have been analyzed.

Customer and strategic evidence has been retrieved.

A prioritized top-3 risk list has been drafted.

Each verified recommendation contains traceable evidence and rationale.

The PM has reviewed the recommendations.

The approved top-3 list is posted to #pm-daily.

Approved Jira stubs are created when required.

Failure

Tool failure: More than 2 tool errors in one run → stop the workflow, log the failure, and notify the PM that analysis is incomplete.

Missing strategy: If the Strategy One-Pager cannot be retrieved → stop prioritization and return "No strategy source available."

Conflicting strategy: If retrieved strategy clauses materially conflict → stop automatic ranking for the affected item and escalate to the PM.

Insufficient evidence: Confidence <30% → return "Insufficient evidence" rather than inventing a recommendation.

Timeout: 90-second wall-clock limit → stop and return available partial results clearly labeled "Incomplete — workflow timed out."

**Fail-Safe Boundaries**

Juno can:

READ Slack #escalations

READ the RocketShip Strategy KB

READ approved Salesforce ARR fields

DRAFT priority recommendations and top-3 rankings

WRITE approved Jira stubs after PM confirmation

POST an approved summary to #pm-daily after PM confirmation

Juno cannot:

Modify Salesforce records

Edit or delete existing Jira tickets

Respond directly to customer escalations

Post outside #pm-daily

Invent strategic evidence

Write an unverified recommendation to the roadmap

Publish or operationalize a prioritization decision without PM approval
